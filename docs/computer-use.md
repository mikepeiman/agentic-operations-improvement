# Computer Use: value and consent

**Purpose:** Decide whether live computer access is worth proposing and preserve the owner's authority over it.

**Constraints:** Existing owner and project permissions govern. This guide grants no access, account authority, automation setup or permission to discard work. Authorized CLI delivery remains distinct from live UI inspection and control.

## Choose whether Computer Use is warranted

Owner, November 8, 2026: "Stop looking to take over my computer, unless it is truly a high-value and unique reason."

When the needed information is a simple visible condition, agents must ask the owner
directly. Before proposing Computer Use, agents must identify the precise information
or result it would provide, why the owner's answer or authorized file/CLI evidence
cannot reasonably provide it, and why the benefit warrants the interruption and access.
A possible convenience does not establish that value. A missing diagnostic discriminator
is an engineering finding; it does not itself establish a need for live computer access.

## Obtain bounded consent

When live desktop or browser access is warranted, the agent must describe the target
app, window or session, purpose and proposed inspection or control actions, then wait
for express consent to that scope. This applies before initialization, discovery,
screenshots and accessibility inspection, including read-only access. General task
requests, tool availability and saved approvals do not replace scoped consent.

When the owner refuses or revokes consent, or the agreed scope ends, agents must stop
that access. They must not substitute a shell UI driver or another automation tool to
bypass the boundary. Independently authorized repository work and isolated tests may
continue without attaching to the owner's live app, profile or session.

Routine delivery permissions come from the adopting project's actual grant. An agent
must not turn an already authorized CLI installation into a request for Computer Use
permission, nor use that installation grant to justify unrelated live UI inspection.
