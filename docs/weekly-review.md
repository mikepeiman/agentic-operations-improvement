# Weekly project review

Run weekly at the owner's chosen day, time, and timezone, or on an explicit
review request. Daily work maintains its own Beads and affected documentation;
this review examines coherence across them. Scheduling belongs to the project's
chosen scheduler and is not implied by copying this file.

Read the project's instructions and existing review Bead; search before creating
one. Pull shared Beads state before mutation. Inspect work changed since the last
recorded review, open priorities and dependencies, and the governing documents
needed to resolve specific questions. On the first review establish that baseline.

Check domain terms and their relationships (the ontology), accepted product and
architectural decisions, and the documents that own them. Look for gaps,
contradictions, deviations from intent, stale guidance, and duplicate meanings.
Check that priorities and dependencies reflect accepted direction, incomplete
work has acceptance criteria and a next action, and captured ideas have not become
implementation commitments by accident. Include closed records when checking for
duplicates or recurring interest.

Apply the core's capture and conflict rules. Update matching Beads and link
evidence; preserve history when consolidating duplicates. Correct authorized
documentation drift in its governing source. Ask the owner about conflicting
intent, ambiguous priorities, or product changes before resolving them. Continue
independent review work while the question is pending.

Record review date, examined scope, actionable findings or absence of findings,
and remaining questions on the review Bead. Link affected task Beads instead of
creating a parallel report collection. Commit and sync any changed tracked state
through the project's delivery workflow. Completion means the examined scope and
findings are captured, not that every discovered issue has been implemented.

When automated, stay quiet while state is unchanged or non-actionable. Notify the
owner for meaningful findings, failures, or required decisions. Avoid a routine
notification solely to say the weekly run finished.
