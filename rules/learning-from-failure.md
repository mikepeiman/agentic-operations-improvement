# Learning from failure

Create a durable corrective record when any of these occurs:

- completion was claimed but the promised boundary failed;
- the same defect recurred;
- an explicit instruction was violated;
- an unsafe or unauthorized mutation occurred;
- a proxy or tool was trusted after its context was shown to be invalid;
- a materially better pattern was discovered after backtracking.

Record:

1. expected and actual result;
2. affected artifact or user impact;
3. missed evidence or mistaken premise;
4. decisive diagnostic;
5. corrective action;
6. narrow trigger and observable completion for any derived rule.

Promote a lesson to an always-on shared rule only when it prevents a recurring
cross-project failure class. Keep product meaning and local commands in the
project or an adapter.

**Observable completion:** the record identifies a future trigger and a
checkable changed behavior, not merely an apology or general aspiration.

Incident: Pax Fluxia accumulated many overlapping always-on rules from local
failures. A prior distillation reduced them, but the active layer later grew
again. Promotion without routing and consolidation recreates the attention
failure the rules were meant to prevent.
